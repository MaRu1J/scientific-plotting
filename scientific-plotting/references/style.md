# Scientific figure style contract

## Locked defaults

| Aspect | Rule |
| --- | --- |
| Canvas | White. Standalone plots use a 4:3 canvas: `single` 90 × 67.5 mm, `medium` 140 × 105 mm, `double` 190 × 142.5 mm, `aip-single` 85 × 63.75 mm, `aip-double` 170 × 127.5 mm. There is no `multipanel` size; multi-panel figures use `render_multipanel` and may grow in height up to 210 mm. An explicit `height_mm` may leave 4:3 when that ratio cannot show the data, and must stay within 40–210 mm. Arbitrary widths are refused. For line-like figures, leave visible margins around the axes (about 13.5% left, 9% right, 13% bottom, 5% top, expanding as needed for labels); do not stretch the canvas to fill it. |
| Font | Arial first; warn and use Liberation Sans if unavailable. Explicit Times New Roman requests warn and use Liberation Serif if unavailable. Chinese text uses 思源黑体 (Noto Sans CJK SC or Source Han Sans SC; warn and use WenQuanYi Micro Hei if neither is installed) or 思源宋体 (Noto Serif CJK SC or Source Han Serif SC; warn and use AR PL UMing CN if neither is installed). Check text layout after substitution. Do not switch an English figure to a Chinese face merely because one is installed. |
| Axis labels | Superscripts and subscripts are written `t^*` (preferred for dimensionless time), `t^+`, `x^2`, `10^-3`, `t_{wall}`, or the same math inside `\(...\)` or `$...$`. A literal caret or underscore is `\^` or `\_`. Chinese characters in an axis label require 思源黑体 or 思源宋体. |
| Text sizes | At final output size, 85 mm and 90 mm figures use 10 pt axis names, 8.5 pt tick labels and legend, 10.5 pt optional title. 140 mm, 170 mm and 190 mm figures use 11 pt axis names, 9.5 pt tick labels and legend, 11.5 pt optional title. Colorbar tick labels follow tick size. Never shrink legend text to force it inside; try another position, then outside or ask for a larger preset. Keep the intended print width. The journal review may warn when text is below the snapshot minimum; it does not silently change these sizes. |
| Frame/ticks | All four spines and both-side tick marks; major and minor ticks directed inward. If a mark obscures boundary data, an explicit exception may move ticks outward. |
| Grid | Numeric axes have visible mid-gray solid major lines and lighter but legible dashed minor lines, behind the data. Linear axes use AutoMinorLocator; log axes use base-10 LogLocator with decade majors and 2–9 minors (2/5 for crowded decades below 60 working pixels after layout), including residual plots spanning ten decades. Never use AutoMinorLocator on log axes. Gridlines within 4 pt of the frame are hidden so they cannot double the border; ticks remain visible. Bar and violin use the value axis only. Heatmap has no overlay grid. |
| Legend | Try non-overlapping locations inside first, with upper center first; vary the number of columns before leaving the axes. Explicit `legend="outside"` skips inside trials. Outside legends use a horizontal band above the axes, then below them if the top band does not fit. Do not put a legend in the left or right margin: that narrows the plot in a column that is already paid for. Never shrink its font to make it fit, and refuse labels that cannot fit. When a single-column plot needs an outside legend, warn that the plot area is reduced and suggest the double-width preset. |
| Color | Ordered numeric/datetime groups progress from a dark amber through yellow-green and green to deep blue-teal (early → late). A single ordered series uses the deep blue-teal stop. Stops are dark enough for a thin line on white and step down in lightness; counts other than five are blended in Oklab, not sRGB, so intermediate colors stay on that path. Unrelated methods use a separate categorical set with separated hues (blue, orange, green, magenta, then olive, red, indigo, and neutral gray). Do not repeat a near-duplicate teal or brown. Marker shape and line style still carry identity in grayscale and for red-green deficiency. These colors are not a formally certified color-vision palette; the amber-to-teal ramp in particular can compress for protanopia, which is why shape and line style stay mandatory. |
| Stroke and markers | For line and point-line plots, measure adjacent points *within each series* after layout, not nearest points across series. Sparse spacing uses 1.5 pt lines and 6.2 pt markers; ordinary spacing uses 1.2 pt and 5.0 pt; close spacing uses 1.0 pt and 3.8 pt; only extreme within-series crowding uses 0.7 pt and 2.6 pt. Manual line widths must stay within 0.5–1.5 pt. Point-line markers are filled with the series color. Markers of at least 3.6 pt have a white edge so the symbol separates from its line; smaller markers omit that halo so dense runs do not turn into a comb. Shapes cycle through circle, square, triangle, diamond, down-triangle, and pentagon, then line style changes. Do not use plus, x, or sideways triangles as defaults: they collapse at these sizes. Plain lines have no markers. Scatter uses its own nearest-neighbor rule: 6.2 pt normally, 5.0 pt when dense, with a dark outline, subtle transparency, and the same shapes. Marker sizes are diameters in pt (scatter area is diameter squared). Optional explicit `--line-width` and `--marker-size` override automatic sizing for applicable kinds. |
| Output | JPEG (`.jpg`) only when unspecified: 300 dpi, quality 95, no chroma subsampling, white background. TIFF only when explicitly selected. PNG, SVG, PDF and EPS are refused. Omitted TIFF dpi follows the journal snapshot (Elsevier 1000/500, JFM 1200/600, PoF 600); an explicit dpi is honored and a shortfall is only a review warning. |

For point-line plots, connect data points in source-row order *within each group* and show markers. Plain lines omit markers; scatterplots never connect them. Do not fit or smooth. A trend line, error bar, shaded uncertainty band, significance mark, or ratio must have an explicit data basis and definition. The template does not add any of these by itself. The agent decides whether error bars are justified and then passes `error_bars` with magnitudes and a definition; see Optional error bars. Do not interpret a color band as a confidence interval without a statistic supplied by the data or the user.

The overall aspect ratio comes from one of three presets; long legends may use a larger preset rather than arbitrary resizing. Line-series overlap alone does not force thinner lines or smaller points; scatter overplotting uses moderate transparency without removing observations. These are presentation-only adjustments: never remove points or change their order. Axis labels should contain units when applicable. Do not draw an in-figure title for a journal figure: the manuscript caption (for example “Fig. 3 …”) is the title, and omitting it leaves the top band free for a legend. Pass `title` only when a title inside the canvas is explicitly required; it still cannot replace the axis labels. For heatmaps, use a perceptually uniform scale, colorbar and readable category labels. Bar groups require pre-aggregated values, not silently summed repeated observations. Repeated long-form heatmap cells similarly require explicit aggregation.

The user's reference image is a *style example*, not a source of experimental data or permission to recreate its curves. "Origin-like" here describes the requested framed axes, typographic balance, breathing room, grid hierarchy and distinct plotted series, not a claim to reproduce a specific OriginLab graph template. If journal instructions conflict, apply them only to the requested figure and state what differs from this default.

## Native CFD comparisons

- `xscale` and `yscale`: `linear` by default; `log` for positive numeric line/point-line/scatter/mixed input. Reject nonpositive values before plotting or export; no filtering or clipping of source values. These options do not change bar/violin categorical or heatmap matrix semantics (nonlinear scales are refused for those kinds).
- `series_styles`: mapping from stringified group label to an object with optional `color`, `linestyle`, `marker`, `line_width` (pt), `marker_size` (diameter, pt). Numeric group `180` is keyed as `"180"`; an ungrouped series is keyed as `""`. Unknown or ambiguous labels and unknown style keys raise errors. A per-series `kind` may repeat the native kind but cannot override it unless the whole plot is explicitly `mixed`. Mixed requires `kind` for **every** series. Line rejects markers; scatter rejects connecting styles; point-line requires both visible line and marker. Custom JSON dash patterns use `[offset, [on, off, ...]]`.
- Stroke sizing measures each connected series' own consecutive, in-frame points in **final transformed display coordinates**, after log scaling and outside-legend layout. Distances are normalized to the template's 120-dpi working canvas so changing export dpi does not alter the physical style. Thresholds remain 4/12/26 working pixels. Never pool density across connected series; do not sort or skip markers. Point-line markers stay filled in the series color; a white edge is applied only when the marker is at least 3.6 pt. Scatter keeps the separate nearest-neighbor convention, evaluated per series, with 6.2/5.0 pt diameters and dense alpha 0.85. Only the density diagnostic is sampled (up to 800 scatter positions), never the plotted data. Pure scatter sits above connecting lines in mixed plots.
- Size priority: per-series explicit size, then applicable global explicit size, then automatic. Marker shape, line style and color stay fixed. Legend handles and reference-error panel artists copy the **resolved main-plot** size/fill/dash identity, even if the error panel has different apparent density. Error-bar caps are not part of that stroke sizing.
- `error={"reference": "Theory", "definition": "signed"}` adds a shared-x, **linear-y** lower panel within the same physical size preset, without adding a fit, smoothing, uncertainty band, error bar, or a reference-zero curve. `signed = y-reference`, `absolute = abs(y-reference)`, `relative = (y-reference)/abs(reference)`; relative is a fraction, **not percent**. The reference is shown only in the main plot, comparisons in both panels. Signed/absolute error has the input y units; set `error["ylabel"]` (CLI `--error-ylabel`) when units need spelling out.
- Grid policy defaults to `interpolation="none"`: require exactly equal coordinate arrays in the same order. Equal row counts or nearly equal floats are not proof of matching grids. Explicit `interpolation="linear"` evaluates the reference in original **data** coordinates, not log space, at each comparison position in its original order. Require strictly increasing unique reference coordinates only when interpolation is actually needed; never sort them or extrapolate. Matching nonmonotonic coordinate arrays may be subtracted directly without reordering.
- Relative zero policy is `zero_reference="raise"`, the only implemented policy: if a reference evaluated at a comparison coordinate is zero, fail clearly before export. Select signed/absolute error or explicitly supply a scientifically justified nonzero domain; do not add epsilon, mask zeros or silently omit rows.
- API metadata: `figure.scientific_error_axes` gives the lower Axes (or `None`); `figure.scientific_metadata` records scales, resolved sizes, reference, formula, zero policy, and per-series exact/interpolation method plus error coordinates/values. `error_bars` is `null` unless uncertainty bars were requested. An export writes `<basename>_metadata.json` when either an error panel or error bars are used; the returned `paths` remain image paths only. The CLI pins the JSON series config alongside its usual template and launcher. The complete CFD validation bundle additionally pins CSVs and parameters for relocatable offline replay.
- Optional [delivery review and bundles](delivery.md) apply to both plotting APIs. `report=True` rereads actual images and saves separate JSON/Markdown reviews. `bundle=DIR` implies review and supports relative-path offline replay; it excludes the legacy numeric metadata sidecar and omits all input snapshots unless `include_data=True`. Existing sidecars beside the original export remain unchanged and may contain numerical arrays; they are not automatically safe to share.


## Optional error bars

- The agent, not the user, decides whether a figure needs error bars. Draw them when an uncertainty column belongs to the plotted value, or when replicate rows should be summarized as a mean. Do not draw them for a single series with no uncertainty information. A solver-error metric, residual or tolerance is not an uncertainty column just because it is named `error`. The user does not have to say "add error bars." Ask only when two different statistics would change the claim, or when the user already gave a conflicting instruction. State the statistic, n, and units in the caption note and in `definition`.
- `error_bars` draws uncertainty bars on `line`, `point-line`, `scatter`, `mixed`, and `bar` only. Heatmaps and violins refuse it. It does not compute a standard deviation, standard error, or confidence interval, and it does not aggregate replicates.
- Magnitudes are non-negative and already in the plotted axis units. `y` or `x` is symmetric. `y_lower`/`y_upper` (and the x pair) are asymmetric and must be supplied together; do not mix a symmetric value with a pair on the same axis. A string names a column, a scalar repeats one magnitude, and an array or Series supplies one value per row in the current row order. A Series with a different index is refused rather than reindexed. Zero is allowed. Negative, missing, and non-finite values are refused.
- `definition` is required text recorded in `figure.scientific_metadata["error_bars"]`. It states the scientific meaning, for example `sample standard deviation, n=4`. The template does not turn that text into a calculation.
- Default cap half-length is 2.2 pt and stem width is 0.8 pt (`capsize`, `elinewidth`). Automatic line and marker sizing does not change them. Every supplied row gets a bar; crowded caps are disclosed, not subsampled.
- Line, point-line, scatter, and mixed bars use the series color and sit behind that series' markers. Scatter bars stay above connecting lines. Bar charts accept y bars only, drawn in `#333333` at the bar centers, because x is categorical. Missing group/category pairs are refused instead of imputed.
- A log axis refuses a whisker whose lower end is zero or negative. No whisker is clipped or dropped. Error bars are not copied onto a reference-error panel and are not propagated into that panel's values.

## Algorithm-comparison extensions

Read [algorithm comparisons](algorithm-comparisons.md) for `style_registry`, explicit constant/power `reference_guides`, `inset`, rectangular `layout`, `heatmap_scale` and `shared_colorbar`. These extend the central template without replacing the frame, grids, palettes, typography or export rules. Insets copy all data and resolved main styles rather than adapting independently. Standalone exports also save `_metadata.json` when guides or an inset are supplied. Composition metadata remains on the figure. The original automatic behavior is preserved when the new options are omitted.
