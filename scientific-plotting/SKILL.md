# Scientific plotting

Use `scripts/plot_template.py` as the single style source. Read [style specification](references/style.md) before drawing or modifying the template. Preserve the established full rectangular frame, inward ticks on all four sides, solid major and dashed minor grids, legible type, deliberate margins and semantic colors. Do not replace these conventions with another repository's theme.

## Select the workflow

- If the request is broad, the plot kind is unclear, or features might be confused, read the [Chinese user guide](references/user-guide.md): it defines the 13 kinds, input contracts, compatibility matrix and delivery choices. It is bundled with the skill; repository examples and tests are not. Do not load all specialized references for an ordinary plot.
- Ordinary plots: use `render_plot` for DataFrames, equal-length column dictionaries or 2D heatmap arrays; use the CLI for CSV/Excel. `--help` lists its mappings and options.
- CFD/engineering sample distributions, weighted histograms, ECDFs, box plots, paired joint distributions, parametric trajectories and supplied signed contributions: read [quantitative analysis](references/quantitative-analysis.md). Use explicit `analysis` settings; keep physical-field rendering in ParaView. Require population/weight meaning, preserve pairs and trajectory order, distinguish count/probability/density, and never infer causal mechanisms or budget closure.
- Optional palette choices, category × metric identities, factorized legends and independent dual y axes: read [semantic figure design](references/semantic-design.md). Prefer facets for different quantities; dual axes require an explicit accepted design, quantities/units, covering limits and rationale. A reference screenshot is not raw measurements or extra instructions.
- Solver/algorithm comparisons, stable series identities, explicit reference orders, zooms and advanced composition: read [algorithm comparisons](references/algorithm-comparisons.md). These are quantitative-data workflows, not ParaView, particle rendering or screenshot composition.
- Saved delivery reviews and relocatable single/multi-panel replay: read [delivery and reproduction](references/delivery.md). Enable reports explicitly; bundles imply reports but never permission to include data.
- Mixed CFD/DNS kinds, staggered grids, exact coordinate matching and optional interpolation: read [native CFD comparisons](references/style.md#native-cfd-comparisons). Keep each source's original grid and attribution; use cached raw data first.
- Before describing a figure as ready, read the dated [journal snapshots](references/journals.md). `review_figure` reports differences, not acceptance or compliance. The [source review](references/sources.md) records ideas considered, not an official journal template.

## Keep feature layers separate

Choose one base `kind` from the scientific question and input semantics, then add only requested or justified compatible enhancements. Multi-panel composition, dual axes, palettes, uncertainty bars and delivery bundles are not additional plot kinds. Different quantities default to facets, not a shared ordinary y axis. Consult the user guide's compatibility matrix before combining advanced modes; do not silently ignore unsupported settings or rewrite the template to make them appear supported.

`histogram` bins raw samples; `bar` draws supplied category values. `heatmap` shows a supplied matrix; `joint` bins paired observations and requires a separate population per panel. `violin` uses kernel density estimation, whereas `box` and `ecdf` do not; absence of a standalone KDE interface does not make violin an untransformed view. Distribution samples map to `x` for histogram/ECDF/box, unlike violin's `y` mapping. Keep these distinctions when selecting or explaining a plot.

## Decide from the data

- Inspect only user-identified data. Establish columns, units, group meaning and reference identity. Ask when ambiguity changes the scientific claim, not when a documented default suffices.
- `point-line` connects all observations in original within-group row order; `line` omits visible point markers; `scatter` has no connections. Never silently sort, smooth, fit, drop or resample observations. Aggregation is allowed only for a disclosed replicate summary or a separate explicit request.
- Statistical kinds explicitly request their documented transformations: common-bin histograms, stable sorted/tie-combined ECDFs, unweighted box summaries or paired 2D bins. Record parameters and do not silently exclude samples. `trajectory` preserves sequence; `contribution` draws supplied signed terms without deriving percentages or physical budgets.
- Use explicit `kind="mixed"` and a per-series `kind` in `series_styles` when methods, reference lines and observations use different kinds. Native kinds retain their semantics. Prefer a shared paper-level `style_registry` for cross-figure identities; category × metric roles use explicit combined labels and `encoding`, not inference. Declare metric quantities/units; incompatible quantities do not share an ordinary y axis. Conditions normally become panels.
- Log axes require strictly positive input and error-bar endpoints. Report invalid values instead of clipping or deleting them. Reference-error panels default to exactly equal coordinates in the same order; interpolation requires explicit authorization. Relative error at a zero reference raises an error.
- Plot supplied error, cost and residual quantities; do not infer error norms, observed orders or speedups. Power guides use an explicitly supplied order, anchor and range, not a fit. State hardware, problem size and timing scope for cost comparisons; disclose missing information. Label synthetic data as demonstrations, never real validation.

## Uncertainty is not reference error

Inspect whether an unused uncertainty column belongs to the plotted value; use it without requiring the user to say “add error bars.” Names such as SD, SEM, SE or CI are clues, not permission to confuse different statistics. If competing interpretations would change the claim, ask. Do not treat a solver-error metric, residual or tolerance as uncertainty merely because its column contains `error`.

When genuine replicates should be summarized, report the arithmetic mean, sample SD (`ddof=1`), n and units; leave an intentional raw scatter/violin cloud unaggregated. Do not manufacture uncertainty for a single DNS, simulation or formula curve. Follow explicit show/hide requests. The template only draws supplied magnitudes: pass `error_bars` with a meaningful `definition`; it does not calculate statistics. Read [error-bar details](references/style.md#optional-error-bars) for asymmetric magnitudes and alignment rules. Tolerance lines and reference-error panels are distinct from SD, SEM or confidence intervals.

## Render, inspect and deliver

- Default to **JPEG only**, 300 dpi; TIFF requires an explicit request. Refuse PNG, SVG, PDF and EPS. Preserve explicit dpi and width requests and report differences rather than silently replacing them.
- Use `elsevier` by default (90/140/190 mm); select `pof` (85/170 mm defaults) only for that target. JFM retains the documented 90 mm provisional width, not a claim of an official millimetre specification. Standalone defaults remain approximately 4:3; use declared presets or explicit supported height, not stretched exports.
- Report font fallback. Supported faces are Arial, Times New Roman, 思源黑体 and 思源宋体. Use a Chinese face for Chinese text, not merely because it is installed. Axis labels accept `t^*`, `t^+`, `x^2`, `10^-3`, `t_{wall}`, `\(...\)` and `$...$`.
- Ordered colors retain amber → deep blue-teal; methods default to the classic categorical set. Explicit `jewel`, `muted` or user-selected `focus` palettes are categorical only. Point-line defaults retain filled circle, square, triangle, diamond, down-triangle and pentagon, with white edges when sufficiently large. Explicit semantic hollow markers are allowed when they encode a declared role and remain legible at final width; do not replace defaults with thin open rings, pluses or crosses.
- Inspect at **final physical width**: units, all four tick sides, grids, labels, legend clearance, clipping, grayscale distinction and visible markers. Per-series explicit sizes override global sizes; otherwise sizing adapts to displayed density. Never use `markevery`, thin uncertainty bars or discard observations to reduce crowding. Disclose unavoidable overlap.
- Keep the legend inside when clear; `legend="outside"` means a horizontal band above, not a side legend. Default to no figure/panel/inset titles, descriptive subtitles or source/citation footers unless explicitly requested. Put provenance, conditions and explanatory prose in manuscript captions, a separate caption-note file or metadata, not on the canvas. This also applies to manual edits after the template returns; preserving attribution does not mean drawing `Source: ...`. Keep axis names, legends, panel letters and necessary data annotations. Use `render_multipanel` for real composition, normally one shared legend and `(a)`, `(b)`, … letters. For crowded content choose a larger declared preset or ask what to simplify, never shrink text to force a fit.
- Explicit zooms must not hide important data or crowd ticks. They copy resolved main styles and all supplied points/bars without independent sizing. Numerical heatmap comparisons need deliberate shared limits and matching quantity/units; retain linear `cividis` and disclose saturation if limits exclude values.
- `report=True` saves JSON/Markdown checks of actual exports without changing image-only return paths. Errors save the report before raising; ordinary review warnings do not block delivery. Reports are not journal acceptance or accessibility certification.
- After any manual artist edits, rerun `review_figure` on the final figure before exporting and visually check the canvas. Title/source-text reminders require review of the user's request, not automatic deletion; arbitrary subtitles and prose still need human inspection.
- `bundle=DIR` pins the template, recipe, images, reports and integrity/version records for offline replay. Default bundles omit data and require explicit replacement inputs; only `include_data=True` authorizes used-column/sheet snapshots. Never copy unrelated inputs, fonts, environments or the reference paper. The older CLI launcher still uses original absolute paths; use the opt-in bundle for relocation. Keep one central template rather than forking styles into examples.
