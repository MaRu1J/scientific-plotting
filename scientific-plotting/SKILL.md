# Scientific plotting

Use this skill when making or reviewing data-driven research figures. The user's established Origin-like style is the default: a full rectangular axis frame, inward ticks on all four sides, solid major and dashed minor gridlines where appropriate, legible fonts, restrained semantic colors, and deliberate margins around the plotting area. Read [style specification](references/style.md) before modifying the template or making a figure.

## Decide before drawing

- Inspect only the data the user identifies. Confirm column mapping, units, group meaning, and what a plotted uncertainty band or error bar represents. Ask when an ambiguity changes the scientific meaning; otherwise follow the defaults in the style specification.
- Distinguish **point-line** (connect observations in their original row order, within each group) from **line** (same connection without visible point markers) and **scatter** (points only). Never sort, smooth, or fit. Aggregate or omit records only to draw a disclosed mean and error bar from replicates, or when the user asks and the transformation is disclosed. Do not invent uncertainty that the table does not support.
- For CFD theory/numerics/DNS comparisons, use explicit `kind="mixed"` and a `series_styles` mapping (`--series-config` JSON in the CLI); give every series its own `kind`. Native `line` and `point-line` always retain their all-series semantics. Keep visual identity consistent through the central template, not manual example overlays.
- Use native `xscale`/`yscale` (`--xscale`/`--yscale`) for logarithmic residuals or wall-unit profiles. All log-axis input must be strictly positive; report zeros/negatives rather than removing them. Kawamura mean/uu/ww and vv/-uv have separate staggered coordinates: retain each table's original grid and author/reference information; use cached raw files first.
- When small deviations need comparison, explicitly request an `error` panel with a named reference and `signed`, `absolute`, or `relative` definition. Default coordinate matching is exact (including order); only interpolate when explicitly authorized. Relative errors at zero reference raise an error, never drop samples. Read the [error/series contract](references/style.md#native-cfd-comparisons) and README examples. Label synthetic CFD and synthetic observations honestly; never present them as real solver or experimental validation.
- Decide whether to draw uncertainty error bars from the data. Do not wait for the user to request them, and do not add them merely because a comparison might benefit from error analysis. Use an unused column when its name or description is the uncertainty of the plotted value (`sd`, `std`, `stdev`, `sem`, `se`, `stderr`, `yerr`, `xerr`, `error`, `uncertainty`, or a lower/upper or CI pair). If several rows are replicates of the same x and group and the figure should summarize them, plot the arithmetic mean and the sample standard deviation (ddof=1) and state n; leave a deliberate raw replicate cloud as scatter or violin instead of collapsing it. If only one value exists per point and no uncertainty column is present, including a lone DNS, simulation, formula, or residual curve, draw no error bar. Follow an explicit request to show or hide uncertainty. If both a spread and a mean-precision column are present and the figure's claim does not choose between them, ask; otherwise do not ask for permission. Tell the user the statistic, n, and units. The template itself still does not infer or rescale: pass the chosen magnitudes through `error_bars` with that sentence as `definition`. Default replicate bars are sample SD, not SEM and not a confidence interval. A log-axis whisker that reaches a non-positive value is an error, not a clipped bar. This is separate from the reference-error panel.
- Preserve explicit user instructions and target-journal requirements. If the user has not specified an export format, output **JPEG only**. TIFF is written only when requested. Refuse PNG, SVG, PDF and EPS. Use `--journal elsevier` (default), `jfm`, or `pof`. Elsevier widths are 90/140/190 mm. PoF uses 85/170 mm only when the user is submitting there; an explicit Elsevier width is kept and the review warns. JFM stays on the 90 mm single preset and must say that the checked instructions gave no millimetre width.
- Adapt dependencies, path handling and the requested Arial/Times font to the computer; report fallback fonts. Keep the reference image's approximately 4:3 canvas for standalone plots, and let the shared template adjust line weight and marker size to visible point density. Never change the locked frame, grid, canvas, legend, type, or export rules to match another skill. Only change those when the user explicitly requests it.
- Color and point-line markers follow the style specification, not another repository's theme. Ordered groups stay amber to deep blue-teal; methods use the categorical set. Point-line markers are filled, with a white edge when they are large enough, and use circle, square, triangle, diamond, down-triangle, then pentagon. Do not switch them back to thin open rings, plus signs, or crosses.

## Render and inspect

Use `scripts/plot_template.py` as the canonical style source. For a file, run it with `--input`, `--kind`, `--x`, `--y` and `--output` as appropriate; use `--group`, `--value`, `--sheet` or `--index-col` where relevant. Call `render_plot` directly for in-memory tables and arrays. Read [README](../README.md) for complete interface examples. The CLI saves a pinned copy of the template and a reproducibility launcher alongside the exported image; the launcher records the original input path, which must be updated if the data move.

Inspect the resulting image at its intended size: axis labels and units, all four tick sides, real major/minor grids, legend overlap and clipping, color meaning and grayscale distinction. In point-line charts, check that markers remain visible without becoming a solid ribbon; in scatter charts, check that category marks remain distinct. Tune `--line-width` and `--marker-size` when automatic sizing fails, without discarding observations. Fix layout without stretching the size beyond a declared preset. If a figure is too dense, select a larger preset or ask which content to simplify. Report any remaining caveat rather than silently changing the user's visual convention.
Check typography at the **final physical print width**, not at a zoomed JPEG. `single` is 90 mm, `medium` is 140 mm, and `double` is 190 mm; AIP/PoF presets are 85 mm and 170 mm. Do not shrink a wide figure into a narrower column or reduce legend text just to fit it. Read [journal snapshots](references/journals.md) before calling a figure ready. `review_figure` lists differences only; never describe the result as compliant or accepted. For more than one panel, call `render_multipanel` instead of the removed `multipanel` size. Keep one shared legend and panel letters `(a)`, `(b)`, `(c)` unless the user asks otherwise. Do not put a title inside a journal figure.
Put the legend inside the axes whenever it does not cover data. Use `--legend outside` only when it must leave the axes; that places a horizontal band above the plot, not beside it. Omit the in-figure title on journal figures so the caption (Fig. N) and the top legend do not compete. Automatic stroke sizing is per series after final axis scaling and legend layout; explicit per-series sizes override global sizes. An error panel reuses the main series' resolved styles, not a second independent adaptation. Error bars keep their cap size and are drawn at every supplied row; do not thin or subsample them when caps crowd. Dense overlaps can remain even when every point is correctly retained and marked; disclose this rather than silently using `markevery` or deleting points.

When extending chart types, edit central style constants and tests rather than forking visual rules into unrelated scripts. The [source review](references/sources.md) explains how four reference projects informed this original implementation and how to keep attribution honest.
